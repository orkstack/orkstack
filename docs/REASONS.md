# Error reasons

Every terminal failure and every refusal carries a machine-readable reason and a human-readable message (AGENTS.md §15). This page has one row for each reason that the code declares as a named constant in `internal/task`, `internal/orker`, `internal/engine`, `internal/dsl` and `internal/authz`. It also has rows for the reasons that the engine writes inline as string literals, such as `RUN_FAILED`, and for the lowercase evidence tokens. Each reason is spelled exactly as the code spells it, so a client can match on it.

Event types, the `Event*` constants in `pkg/webhooks`, are not failure reasons and are not listed.

The **Category** column is the failure category the code assigns (see [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). Retry follows the category: `ActivityFailed` and `InfrastructureError` are retried under the task's `retry:` policy, and `ContractViolation`, `TimedOut` and `Cancelled` are not. Where a row states a retry outcome, the code or the contract states it. A dash means the code carries no failure category. Most dashes are refusals or cache misses, and `PANIC` is recorded but never reported as a reason.

## Submit and admission

A refusal here happens before a run ID is minted and before an idempotency key is claimed, so a refused submission leaves nothing behind ([DEPLOY.md](./DEPLOY.md#namespace-admission-hold-and-max_running), "Namespace admission"). The image policy is checked again at create, and by the Orker when a task is dispatched.

| `NAMESPACE_HELD` | — | The namespace is on hold, so it accepts no new runs. Releasing a hold starts nothing that was refused while it was set. |

It is refused at submit, and `allow_empty_pool` does not change that. | `FOREIGN_SECRETS_UNBOUNDED` | — | A shared Orkflow composed from another namespace names a secret, and the namespace it runs in sets no `allowed_secrets`, which leaves only its own Orkflows unrestricted ([DSL.md](./DSL.md#sharing-across-namespaces), "Sharing across namespaces"). | List the sources the namespace may read with `orkctl namespace update NS --allow-secret PATTERN`. The shared Orkflow is then held to that list. |
| `SHARED_ORKFLOW_NOT_ROOT` | — | Run again names a child run of another namespace's shared Orkflow. Such an Orkflow runs only as a child, never as a root run ([DSL.md](./DSL.md#sharing-across-namespaces), "Sharing across namespaces"). | Run its root run again; the message names it. |
| `CONCURRENCY_KEY_INVALID` | — | A concurrency limit's key breaks the key rule (1 to 128 bytes of letters, digits and `. _ : / @ + = -`, starting with a letter or digit, not `ork:`), or its template did not render, such as an input it reads that the run does not have. A literal key is refused at validate, a rendered one at submit (`INVALID_ARGUMENT`), naming the template and the first bad byte ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). | Fix the key template, or submit with the input it reads. |
| `CONCURRENCY_UNSUPPORTED` | — | The Orkflow declares a concurrency limit this deployment cannot hold. `cause=index`: the cluster does not index the attributes a limit is kept by. `cause=fleet`: an engine process runs a release without concurrency limits (`concurrency-1`); a trigger's `503` carries the code alone, the cause is the API's. Or the limit is declared by an Orkflow that would run as a composed child, which this release does not hold ([DEPLOY.md](./DEPLOY.md), "Which capabilities exist"). Submit a limited Orkflow as a run of its own. |
| `CONCURRENCY_LIMIT_REACHED` | — | The run's concurrency limit is `on_limit: refuse` or `skip`, and every slot of its key is held. Refused `FAILED_PRECONDITION` at submit, before a run id exists, naming the runs that hold the key and any that are not making progress. A holding run that has ended counts as free ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). | Submit again once a run holding the key ends, or end a stalled one. Use `on_limit: queue` to wait instead. |
| `CONCURRENCY_QUEUE_FULL` | — | The run would wait in a concurrency limit's line, and that line is full: `cause=max_queued` (the limit's own `max_queued`), `cause=max_entries` (the most one key holds, `engine.concurrency.max_entries`), or `cause=namespace` (the namespace's queued runs, `engine.concurrency.max_queued_runs_per_namespace`). | `CONCURRENCY_KEYS_EXHAUSTED` | — | The run's key is new and the namespace already has as many keys with runs holding or queued as it may (`engine.concurrency.max_active_keys_per_namespace`). Refused `RESOURCE_EXHAUSTED` at submit, best-effort. | Submit again once a key is free, or render fewer distinct keys. |
| `CONCURRENCY_CHECK_UNAVAILABLE` | — | Whether the run's concurrency limit can be held, or would fit, could not be checked: the cluster's list of engine processes (`scope=fleet`), the key's line (`scope=key`) or the namespace's counts (`scope=namespace`) could not be read. The submit is refused `UNAVAILABLE` and leaves nothing behind. A trigger's `503` carries the code alone; the scope is the API's. | Submit again. |
| `INPUT_TOO_LARGE` | ContractViolation | The run's input is over 256 KiB, so it is refused at submit and at a schedule's fire. The same code is raised when a task's input would exceed the limit at dispatch ([DSL.md](./DSL.md#inputs), "Inputs"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Pass a reference to large data, such as a URL or an object key, instead of its bytes. A deep chain that fails at dispatch is split into composed Orkflows ([DSL.md](./DSL.md#how-many-tasks-an-orkflow-may-declare), "How many tasks an Orkflow may declare"). |

## Authorization

With `auth.mode` `observe` or `enforce`, a request is decided against the access document before any handler runs ([ACCESS.md](./ACCESS.md#how-a-request-is-decided), "How a request is decided"). In `enforce` mode these refuse the request; in `observe` mode they are recorded as `would-deny` and the request is served. A run the caller may not read is answered `not_found` instead, as one that does not exist.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `PERMISSION_DENIED` | — | No binding grants the caller the permission at a scope that covers what the request names. The message names the caller, the permission and the scope, and never a binding ([ACCESS.md](./ACCESS.md#permissions), "Permissions"). | Ask an administrator for a binding of a role that holds the permission, at that scope or a wider one. A list paged by a key walk names the filter to add instead. |
| `PRINCIPAL_DISABLED` | — | The caller's id is under `disabled` in the access document, so it is refused whatever it presents, and its open streams are closed ([ACCESS.md](./ACCESS.md#subjects), "Subjects"). | An administrator enables the principal again, or the caller stops using it. |
| `UNAUTHENTICATED` | — | The request carries no verified caller, where the permission needs one ([AUTHENTICATION.md](./AUTHENTICATION.md#what-the-api-accepts), "What the API accepts"). | Send `Authorization: Bearer` with a token from a trusted issuer. |

## The identity mint

An Orker asks the engine for the tokens of an attempt's identities (`MintAttemptTokens`, `enforce` mode only); a refusal is the attempt's reason with the category below ([TASK_IDENTITY.md](./TASK_IDENTITY.md#the-mint), "The mint"). A step that could not ask is `IDENTITY_UNAVAILABLE`; one that asked and was told no is the refusal named.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `IDENTITY_UNAVAILABLE` | InfrastructureError, retried | A fact the mint needs could not be read: the admission record, the cluster's describe, the attempt cap, the policy, or the record of what was issued could not be written. | Nothing: it is retried. Check the store and the cluster if it persists. |
| `IDENTITY_ENGINE_REFUSED` | InfrastructureError, retried | The engine will not mint: it does not enforce authentication, has no issuer or no eligible key, was not the run's issuer, or cannot check what the task follows. An operator's fault, never the task's. | Run the engine with `auth.mode: enforce`, an issuer and an active key. |
| `IDENTITY_NOT_ADMITTED` | ContractViolation | The run, task, item or token asked for is not what the run was admitted with, or the run was not started as its admission says. | Nothing a retry changes; resubmit the run. |
| `ATTEMPT_NOT_HELD` | InfrastructureError, retried | The cluster does not say the calling Orker holds this attempt now. | Nothing: a hand-over can lag a moment; a gone attempt ends by its heartbeat. |
| `TASK_NOT_AS_ADMITTED` | InfrastructureError, not retried | The task the Orker was dispatched is not the task the engine admitted; the message names the members that differ and the admitting engine's build. | Report it: one release disagrees with itself. |
| `IDENTITY_SPEC_SKEW` | InfrastructureError, retried | The engine found the task differs from its admission, and this Orker runs another build than the engine that admitted it, so the two builds disagree about the task. Set by the Orker; the message names both builds. | Nothing: a retry may run on an Orker of the admitting release. Finish the rollout so every Orker of the pool runs one release. |
| `PROVIDER_UNAVAILABLE` | InfrastructureError, retried | A provider did not answer within the attempt's setup budget, so nothing was started; the message names the provider ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Restore the provider, or the Orker's route to it. |
| `CREDENTIAL_REFUSED` | ContractViolation, not retried | A provider refused the attempt's login, or a credential, for 30 seconds and three answers ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Correct the trust policy or role at the provider, or the grant's principal. |
| `CREDENTIAL_REFRESH_FAILED` | InfrastructureError, retried | A required credential expired because it could not be refreshed, so the Orker stopped the container ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Restore the provider; `refresh: best_effort` lets a task run on without it. |
| `SECRET_ACCESS_DENIED` | ContractViolation, not retried | A provider refused to read a secret for the grant's principal ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Give the principal access, or name another grant. |
| `SECRET_NOT_FOUND` | ContractViolation, not retried | A secret, or a credential's path, is not at the provider ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Correct the `source` or `path`, or create it. |
| `SECRET_TOO_LARGE` | ContractViolation, not retried | A provider's value, or one file of a credential, is over 1 MiB ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Store less, or pass a file as an artifact. |
| `PROVIDER_NOT_CONFIGURED` | InfrastructureError, not retried | This Orker does not declare the provider the run was admitted for, or declares it for another audience ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Give every Orker of the pool, and the engine, the same `providers`. |
| `PROVIDER_CONTRACT_VIOLATION` | InfrastructureError, not retried | What a provider answered cannot be put in place: a file name, a count or a lifetime it may not have ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Fix the provider. |
| `PROVIDER_SETUP_FAILED` | InfrastructureError, retried | The Orker could not prepare the attempt's logins: a fault of the Orker, not of the provider ([PROVIDERS.md](./PROVIDERS.md#failure-reasons), "Failure reasons"). | Report it, with the Orker's log. |
| `IDENTITY_CLOCK_SKEW` | InfrastructureError, retried | The engine issued the token at a time more than 2 minutes from this Orker's clock. Set by the Orker, which writes no token and does not ask again in the attempt. | Fix the clock of the Orker's host or the engine's (NTP). |
| `IDENTITY_REFRESH_FAILED` | InfrastructureError, retried | A required identity's token expired before a refresh replaced it, because the engine could not be asked or could not answer for that long. Set by the Orker, which stopped the container. | Make the engine reachable from the Orker; a `best_effort` identity runs on instead. |
| `IDENTITY_ATTEMPTS_EXHAUSTED` | InfrastructureError, not retried | Every attempt that may hold the task's identities is held by another attempt. | Raise the task's retries or the namespace's `attempts_extra`. |
| `IDENTITY_ATTEMPT_EXPIRED` | InfrastructureError, not retried | The attempt outlived its deadline by the engine's clock. | Nothing: the cluster ends such an attempt. |
| `IDENTITY_REVOKED` | ContractViolation | The namespace's identity policy no longer allows an audience the run was admitted with. | Allow it again, or run without it. |

## Recording a result

An Orker hands the engine an attempt's result for a run whose results the engine records (`CommitResult`, `enforce` mode only; [TASK_IDENTITY.md](./TASK_IDENTITY.md#results-the-engine-records), "Results the engine records"). Steps 2 and 4 to 6 are the mint's, and answer the mint's reasons above: `IDENTITY_UNAVAILABLE`, `IDENTITY_ENGINE_REFUSED`, `IDENTITY_NOT_ADMITTED`, `ATTEMPT_NOT_HELD` and `TASK_NOT_AS_ADMITTED`. A result that is not of the attempt it names is `COMMIT_IDENTITY_MISMATCH` ([The Orker and the container](#the-orker-and-the-container)), and nothing is recorded. A run whose admitted definition is gone, or is not the definition it names, is `IDENTITY_NOT_ADMITTED`. Each is told at once, never as an outage the Orker would wait out.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `IDENTITY_CONSENT_MISMATCH` | — | A save that binds a schedule, trigger or event source whose Orkflow asks for an identity gave no consent, or a consent to a digest other than what the Orkflow asks for now. The message says what changed and hands out the digest; nothing is recorded ([TASK_IDENTITY.md](./TASK_IDENTITY.md#consent), "Consent"). | Review what it asks for and save again with `--consent=DIGEST`. |

## The Orker and the container

The Orker runs each task attempt, and an attempt reports at most one of these reasons. Seven are boot refusals, marked below: the Orker refuses to start, so no task carries them. `RUN_AS_ORKER_UNAVAILABLE` is a task failure, and a boot refusal only on an Orker that runs every task as its own user.

### Container, image and workspace

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `CONTAINER_EXIT_NONZERO` | ActivityFailed, retried | The container exited non-zero. Every non-zero status gives this reason, whatever the number. The message says when the kernel killed the container at its memory limit ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the attempt's stderr. The exit status alone does not say what failed. |
| `CONTAINER_TIMEOUT` | TimedOut, not retried | The Orker stopped the container when the task's `timeout_seconds` ran out: SIGTERM, then SIGKILL after the grace period ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the attempt's stderr to see how far the run got. Raise `timeout_seconds` if the work legitimately takes longer. A timeout is not retried, because it would hit the same limit again ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). |

| `COMMIT_IDENTITY_MISMATCH` | ContractViolation, not retried | An existing commit at this key differs from this attempt on one of seven identity fields. The check fails before the container starts ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#54-the-sequence), "§5.4"). For a run whose results the engine records, the engine also answers it to a result an Orker hands it that is not of the attempt the request names: another schema, namespace, run, task, definition, idempotency key, attempt, Orker or image, a recording of its own, another task's commit key, a result too large to record, or a record already at its key that cannot be read ([Recording a result](#recording-a-result)). A resumed run answers it to a kept result whose commit is another activity's. | Nothing is overwritten or recorded. Start a new run if the work is still needed; report a result the engine refused, since the Orker sent what its attempt did not produce. |
| `COMMIT_UNDECODABLE` | ContractViolation, not retried | The object at the commit's URI is not a readable commit, even after one reread within the attempt. The message names the URI and its size ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#54-the-sequence), "§5.4"). A resumed run answers it to a kept result it cannot decode. | Check object storage for the damaged object, using the URI in the message. |
| `PAYLOAD_ENCRYPTION_NOT_CONFIGURED` | InfrastructureError, not retried | The task's run is encrypted (payload encryption, not yet available), and the Orker that took it has no way to get the run's key. | Configure the pool's Orkers for payload encryption. Every Orker of a pool needs the same settings ([DEPLOY.md](./DEPLOY.md#1-configuration), "§1"). |
| `PAYLOAD_KEY_UNAVAILABLE` | InfrastructureError, retried | The Orker could not get the key of the task's encrypted run (payload encryption, not yet available). The attempt is tried again under the task's retry policy. | Check that the Orker can reach the engine. If it keeps failing, the task fails with this reason once its attempts are spent. |
| `COMMIT_TOO_LARGE` | ContractViolation, not retried | The commit that this attempt would write is over its size limit. The check runs before any upload ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#54-the-sequence), "§5.4"). | Produce fewer outputs, since the commit records a reference for each one. |
| `COMMIT_STORE_NOT_CONDITIONAL` | InfrastructureError, not retried. Boot refusal. | At boot, the Orker found that the object store does not support conditional writes, or answers one of them wrongly (an `If-Match` on a missing key, a conditional `DeleteObject`), so it refuses to start. Without them a commit cannot stay immutable ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#53-the-store), "§5.3"), and an Orkflow rollback could remove another apply's version ([STORAGE.md](./STORAGE.md)). | Use an object store that supports conditional writes, then start the Orker. |
| `COMMIT_STORE_UNAVAILABLE` | InfrastructureError, not retried. Boot refusal. | At boot, the Orker's probe of the object store got no answer about conditional writes: no response, a refused credential, no such bucket, or a server error. The probe proves nothing about conditional writes either way, and the message carries the store's own answer ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#53-the-store), "§5.3"). | Fix what the message names, usually the bucket or the credentials, then start the Orker. |

## The engine and the run

These codes come from the engine: how a run starts and ends, its tasks, its history, joins, pins, awaits, fan-out, composed tasks, declared outputs, routing and plan simulation. A composed task is never retried, and an awaited task has no retries ([DSL.md](./DSL.md#composition-uses-orkflow), "Composition"; [DSL.md](./DSL.md#awaited-tasks), "Awaited tasks").

### Run start

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_START_FAILED` | — (status `FAILED`) | The run's start failed after its run ID was minted. The run is recorded FAILED with no task, pool, Orker, image or phase, and its message is the cause ([STATS.md](./STATS.md#6-failure-fingerprints), "§6"). | Read the message. No task ran, so there is nothing to cancel. Submit the run again. |
| `RUN_START_UNREADABLE` | InfrastructureError, not retried | The run's start could not be read, so the run ended at once without starting anything. Its one event is `RUN_FAILED`, with no task, and nothing of its input or definition was read. This happens to encrypted runs (payload encryption, not yet available) whose start was not sealed for this run or names another namespace or Orkflow than the run's record. It also happens to any run whose start was put into the cluster by something other than OrkStack and does not decode. | Nothing in the run can be recovered. If the work is still needed, submit it again through OrkStack. A run that OrkStack started never ends this way. |
| `INVALID_RUN` | — | The run's start refused a run with no run ID, with the message "run id is required". A client sees `RUN_FAILED` with that message, except for a run carried on by an older release, which reads as `RUN_STATE_UNSUPPORTED` ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Nothing for a client to act on. The submit path mints the run ID before the run starts (AGENTS.md §7). |
| `INVALID_ORKFLOW` | — | The run's start refused an Orkflow with no tasks, with the message "orkflow has no tasks". A client sees `RUN_FAILED` with that message ([DSL.md](./DSL.md#top-level-fields), "Top-level fields"). | Add at least one task to the Orkflow, then apply it again. |

### Run outcomes

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_FAILED` | — (the failing task's category applies) | The run failed. Its message is the cause, and its details name the failing task (`task "<id>"`). A fan-out's or a composed task's failure carries that node's sentence. A pin that lost its host ends the run with this code and the pin's message ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message, then the failing task's own error, which carries its reason code and category. |
| `RUN_CANCELED` | — (status `CANCELED`) | The run was cancelled, so its status is `CANCELED` and its message is "run canceled" ([CLI.md](./CLI.md#orkctl-run-cancel), "orkctl run cancel"). | `RUN_TERMINATED` | — (status `CANCELED`) | The run was ended from outside its own execution. Its message is the termination reason, or "run terminated" when none was given. | `RUN_FORCE_CANCELED` | Cancelled (status `CANCELED`) | An operator ended the run with a force cancel, after an ordinary cancel and its grace: the run did not end on its own. | `RUN_FORCE_CANCEL_UNVERIFIED` | Cancelled (status `CANCELED`) | The run was ended from outside, with a force cancel's record that no engine could verify before the cluster deleted the run. Nobody is named. While there is time, reading such a run fails and is asked again instead; this code is only on an archived run. | Check the engines' signing keys and the published keys document. Start a new run if the work is still needed. |
| `RUN_RECORD_INCOMPLETE` | InfrastructureError, keeps the run's status | The run's archive was built from its history and the record of its tasks could not be recovered from object storage. The run has no error of its own, so this says what is missing. Its outcome, name, input and events are intact. A run that has an error of its own keeps it, and says the same in its details ([DEPLOY.md](./DEPLOY.md), "The archive sweep"). | Nothing brings the record back. Check for a bucket lifecycle rule over `metadata/snapshots/`, which must not exist. |
| `RUN_TIMED_OUT` | TimedOut (status `FAILED`) for a run's own timeout; — for a cluster limit | Two causes. The run's own `timeout:` passed: its message says the limit and the deadline and names the tasks it stopped, its category is `TimedOut`, and its snapshot and archive hold every row ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). Or the cluster ended the run's execution at a time limit set outside the run's start, with the message "run timed out" and no category. | For the run's own timeout, raise `timeout:` in a new version of the Orkflow and run it again. For a cluster limit, start a new run if the work is still needed. |
| `RUN_DEFINITION_UNSUPPORTED` | ContractViolation, not retried | The run's definition declares a feature its plan does not carry, such as a run timeout submitted through a release that did not plan one. The run ends at its first step, after `RUN_CREATED` ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). | Submit the run again once every engine process runs the same release. |
| `RUN_TIMEOUT_STATE_INVALID` | ContractViolation, not retried | The run declares a run timeout but its clock was never started, a state the engine never writes. It ends explicitly rather than run with no deadline ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). | Run it again. Report it if it happens again. |
| `RUN_PAUSE_TIMEOUT` | TimedOut (status `FAILED`) | The run was paused and not unpaused before its pause timed out, or the parent run whose pause held it neither unpaused it nor ended before its backstop. The message says who paused it, when, and until when. A run that was already failing keeps its own reason instead: its message gains the pause's end, and the failure handlers it held did not start. | Start the run again; next time unpause it sooner, or pause it with a longer timeout. |
| `RUN_CONCURRENCY_LIMIT` | — (status `FAILED`) | The run's concurrency limit is `on_limit: refuse` or `skip`, and another run took the key's last slot between the submit's check and the run's own request for it. The run started no task ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). The message names the key and its limit. | Submit the run again once a run holding the key ends, or let it queue (`on_limit: queue`). |
| `RUN_CONCURRENCY_FULL` | — (status `FAILED`) | The line for the run's key was full: it already held as many runs as the deployment allows one key (`engine.concurrency.max_entries`). | Submit the run again later, or raise `engine.concurrency.max_entries`. |
| `RUN_CONCURRENCY_UNAVAILABLE` | InfrastructureError (status `FAILED`) | The run's concurrency limit did not answer within `engine.concurrency.acquire_timeout`, or was still rebuilding its record of running runs when the run's wait ended. | Submit the run again. If it recurs, check the engine's logs for the limit, and the `ork.concurrency.rebuilding` gauge. |
| `RUN_CONCURRENCY_FENCED` | ContractViolation, not retried | The run's concurrency limit refused a request from this run as stale or already released: a clock far behind the engine's, or a request sent again after the run let the slot go. | Submit the run again. If it recurs, check the engine hosts' clocks. |
| `RUN_CONCURRENCY_UNSUPPORTED` | ContractViolation, not retried | The run's concurrency limit could not take its request (`cause=protocol`): the engine that keeps the limit runs a release that does not support it. A failed run that is held to a concurrency limit and was resumed ends with it too, before anything runs again: this release cannot resume such a run. | Finish rolling the deployment out to one release, then submit the run again. Run a resumed run again instead. |
| `RESUME_PLAN_UNREADABLE` | InfrastructureError (status `FAILED`) | A resumed run could not read the plan of its resume from object storage, or the record of the resume from the cluster, before its restore timeout (5 minutes when the run pins none). Nothing ran again, and every task keeps the state it had. A run that could not tell where its earlier events end fails with no event of its own, and reads as ended from its closed execution. | Check object storage and the engine's logs, then resume the run again. |
| `RESUME_PLAN_INVALID` | ContractViolation, not retried | A resumed run's plan is not the one its resume named: it is altered or does not decode, it is of another run or another resume, a newer resume has replaced it, or it needs something this release cannot do. Nothing ran again, and every task keeps the state it had. | Resume the run again. If it recurs, run it again and check the bucket for changes made outside OrkStack. |
| `RUN_QUEUE_TIMEOUT` | TimedOut (status `FAILED`) | The run waited in line for its key for its limit's `queue_timeout` and was never given a slot; or, after an unpause, waited that long to get its slot back ("…after an unpause without continuing"). The message names the key and how long it waited. | Submit the run again; or raise `queue_timeout`, or the limit. |
| `RUN_SUPERSEDED` | Cancelled (status `CANCELED`) | Another run of the same key replaced this one while it waited, by its limit's strategy. The message names that run. | Nothing to do: the run that replaced it does the work. |

### Task outcomes

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `PAYLOAD_UNREADABLE` | ContractViolation, not retried | A task's input, as its Orker received it, or a task's result, a child run's result, a failure sent to the run or a result recorded in its own history, could not be read as this run's, so the task failed. It does not open under the run's key for the run's own id, or it is sealed in a run that has no key. This happens to encrypted runs (payload encryption, not yet available). It also happens to any run sent a result by something other than OrkStack. | Nothing for the run to recover. A result that OrkStack produced always reads, so this means someone wrote to the cluster directly. Treat it as worth an alert. If the work is still needed, start a new run. |
| `TASK_FAILED` | The error's category, if it has one | The default code for a task failure that carries no reason of its own. Its message holds the cause ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message. |
| `TASK_STOPPED_BY_RUN_TIMEOUT` | TimedOut, not retried | The task was running, waiting or sleeping when its run's own `timeout:` passed, so it was stopped and recorded `FAILED`. | `RESUME_NOT_READ_BACK` | Cancelled (status `CANCELED`) | The task succeeded before the run was resumed, and the run ended before its result had been read back. The result is still stored. | Resume the run again: the task's result is kept. |
| `COMMIT_MISSING` | InfrastructureError, not retried | A resumed run keeps this task's result, and the commit that holds it is no longer in object storage ([STORAGE.md](./STORAGE.md)). | Resume the run again and have this task run again, or run the whole run again. |
| `TASK_CANCELED` | Cancelled | The task was cancelled. Its status is `CANCELED`, so it did not fail, and it is not retried automatically ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). | Start a new run if the work is still needed. |
| `TASK_OUTPUT_INVALID` | ContractViolation, not retried | The task's committed `values.json`, or an await's completion, could not be converted into the task's output ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message, which gives the conversion error, and correct the values the task writes. |
| `ACTIVITY_TIMEOUT` | TimedOut, not retried | The activity's own start-to-close limit ended it before the Orker reported a result. Read the attempt's stderr, and raise `timeout_seconds` if the work legitimately takes longer. |
| `ORKER_HEARTBEAT_TIMEOUT` | InfrastructureError, retried | The Orker stopped heartbeating the activity, so it is taken to have died. That is a fact about the host, not the workload. The task is retried, which moves it to a live Orker ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). | Retried. If it keeps happening on one host, check that host. If the attempt's record says `REPORT_UNDELIVERED`, the Orker was stopped and could not tell the cluster so. |
| `ORKER_HEARTBEAT_LOST` | InfrastructureError, retried | Nothing acknowledged the attempt's heartbeat for the 30 s heartbeat timeout, because the cluster was unreachable or too slow to answer. A shorter silence changes nothing. The Orker stopped the attempt as it stops a cancelled one (`SIGTERM` to the container, `SIGKILL` after the task's grace), though nobody cancelled the task, because the cluster has given the attempt up and a retry may start elsewhere. A task that had already written its commit is not affected: it reports its result. Nor is one whose container had already exited by itself: it reports how it ended. The task itself usually reads `ORKER_HEARTBEAT_TIMEOUT`, with this on the attempt's record ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"). | Check the cluster's health and the network between it and the Orker. Give the task a `retry:` if it should survive this, since a task with none has one attempt. |
| `ATTEMPT_STORE_UNAVAILABLE` | InfrastructureError, retried | The Orker could not claim the attempt's ordinal: the attempt store refused or did not answer the claim on four tries over about 10 s. The attempt did nothing: it created no container, wrote no attempt record and streamed no log ([STORAGE.md](./STORAGE.md#invariants-the-layout-carries), "Attempt ordinals"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#71-the-sequence), "§7.1"). | Check that the object store is reachable from the Orker and accepts conditional writes under `metadata/attempts/`. The attempt runs again without spending an own attempt, five times in a row, waiting at least 45 s after the first ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"); past that, under its `retry:`. |
| `RUNTIME_STATE_UNKNOWN` | InfrastructureError, retried | The container's start failed and the container runtime could not then say whether it started: the inspect that decides it failed too, usually because the daemon stopped answering. The Orker stopped the container and removes it, but it may have run, so running the task again can repeat an external side effect; a task with one keys it on `idempotencyKey`. The attempt counts as never started, so the task runs again without spending its own attempts, five times in a row; past that, under its `retry:` ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"). | Check the Orker's container daemon (`docker info` or `podman info` as the Orker's user) and its logs. |
| `RUN_CONTEXT_UNAVAILABLE` | InfrastructureError, retried | The Orker could not read the run's run-context object, which a task's `task.json` is filled from: the store did not answer or refused the read, or this Orker has no store for it. A refused read means the object is missing or the Orker's credential may not read `metadata/run-context/`: on a store that answers alike for both, such as AWS S3, a credential that may not list cannot tell them apart. No container was made ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#71-the-sequence), "§7.1"). | Check that the object store is reachable from the Orker and that its credential may get `metadata/run-context/` ([DEPLOY.md](./DEPLOY.md#an-orkers-own-storage-credential), "An Orker's own storage credential"); if it may, check that nothing deleted the object. Retried under the task's `retry:`. |
| `RUN_CONTEXT_MISSING` | InfrastructureError, retried | The store says the run's run-context object, under `metadata/run-context/`, is not there ([STORAGE.md](./STORAGE.md)). | Check that nothing deletes or expires objects under `metadata/run-context/` while their run lives. Retried under the task's `retry:`. |
| `RUN_CONTEXT_INVALID` | ContractViolation | The run's run-context object is not what its SHA-256 names, does not decode, or has no entry for the run. | Its bytes cannot change, so it is not retried: check what wrote over the object, and run the Orkflow again. |
| `ORKER_STOPPED` | InfrastructureError, retried | The Orker running the attempt was stopped with `SIGTERM` or `SIGINT` and handed the attempt back: a running container got the cancellation sequence (`SIGTERM`, then `SIGKILL` after the task's grace) while the attempt kept heartbeating, and the Orker reported the attempt itself before it exited. It hands back only what still runs when its stop grace (`orker.stop.grace`) ends, or at a second signal; an attempt that reached the Orker after the signal started nothing. The task runs again on another Orker without spending its own attempts while its run's interruption budgets last, then under its `retry:` policy; a task with no `retry:` then fails with this reason ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"; [DEPLOY.md](./DEPLOY.md#removing-an-orker-safely-cordon-and-drain), "Removing an Orker safely"). | Give the Orker a stop grace that covers its tasks, and a stop timeout that covers the grace, or drain it before stopping it: `orkctl orker drain ID`. |
| `REPORT_UNDELIVERED` | InfrastructureError, retried | Found only on an attempt's record (`orkctl run attempts`). The Orker handed the attempt back as it stopped but the cluster never took its report within 10 minutes, so the run sees what it sees of an Orker that died: the task ends `ORKER_HEARTBEAT_TIMEOUT`, or runs again under its `retry:` policy ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"). | Check that the Orker reaches the cluster. |

## Pausing a run

`orkctl run pause` and `run unpause` (the API's `PauseRun` and `UnpauseRun`) check the run before they send anything, and refuse with `failed_precondition` and one of these reasons, which leads the message. The checks read the run as the read model has it, so a request can still race the run's own change; then the run's decision stands, and the request's `RUN_PAUSED` or `RUN_UNPAUSED` event, or its absence, says what it did ([API.md](./API.md#pauserunrequest), "PauseRunRequest").

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_PAUSE_UNSUPPORTED` | — | The run was started by a release without support for pausing, so it cannot be paused. | Cancel it, or let it finish. |
| `RUN_PAUSE_NOT_RUNNING` | — | The run has not started yet, or is waiting for its concurrency slot. | Cancel it if it should not continue, or pause it once it runs. |
| `RUN_ALREADY_PAUSED` | — | The run is already paused, by a person or because its parent run is paused. A pause cannot be changed. | Unpause it, or its parent run, then pause it again. |
| `RUN_PAUSE_INHERITED` | — | An unpause of a run that is paused because its parent run is paused. Only the parent's unpause lifts it. | Unpause the parent run the message names. |
| `RUN_ENDING` | — | A pause of a failing run whose failure handlers have all started, so a pause would hold nothing, or an unpause of a run whose pause has already expired and which is ending. | Read why the run ended, with `orkctl run get`. |
| `PAUSED_FILTER_UNAVAILABLE` | — | A list asked for `status=PAUSED` on a deployment whose cluster does not index paused runs. There, a paused run lists as `RUNNING`, and `orkctl run get` shows it exactly ([DEPLOY.md](./DEPLOY.md#the-paused-run-index), "The paused-run index"). | Register the `OrkflowRunPaused` search attribute and restart an engine. |

## Resuming a run

No build resumes runs yet: `ResumeRun` answers `failed_precondition`, "this engine resumes no runs", and no run says it can be resumed. What follows is what it answers once it is switched on.

`ResumeRun` (the API, `orkctl run resume`, the run page) refuses with `failed_precondition`, a message that begins `RUN_NOT_RESUMABLE`, and one of these reasons in its `ResumeRefusal` detail. The **Class** says what a caller can do: `permanent` (resuming cannot fix it; run it again), `wait` (try again after the seconds it gives) or `replan` (preview again and decide). It also refuses with the admission reasons above (`NAMESPACE_HELD`, `MAX_RUNNING_REACHED`, `BUDGET_EXCEEDED`, `BUDGET_UNMEASURABLE`), as `wait`. Where a reason has a `cause`, it is in the detail. A run that is in another namespace, or that is not there, is `not_found`, as for every other request about a run.

|---|---|---|---|
| `STATE_NOT_RESUMABLE` | permanent | The run is not a failed run: it is running, paused, succeeded or canceled, or it did not end the way its record says. | Wait for it to end, or run it again. |
| `NEVER_STARTED` | permanent | The run ended before it got going, so there is nothing to carry on from. | Run it again. |
| `NO_RESUME_POINT` | permanent | The run's latest part ended before it got going. | Run it again. |
| `NOT_A_TASK_FAILURE` | permanent | The run stopped for a reason that rerunning tasks cannot fix, or none of its tasks failed or was left unfinished. | Run it again. |
| `FAILED_IN_EARLIER_PART` | permanent | The run failed before it carried on into its current part. | Run it again. |
| `FAILURE_NOT_RECORDED` | permanent | The run's ending names no reason. | Run it again. |
| `STATE_UNREADABLE` | permanent; replan with cause `events_above_terminal` | The run's saved state, definition, results or resume records cannot be read back. `events_above_terminal`: the run's stored events go on above its ending by more than `engine.resume.max_seq_gap`, and were not written by its ending; the message names the highest. | Run it again. For `events_above_terminal`, accept the gap with `--accept-sequence-gap` (it needs `run.resume.accept_gap`) after finding out what wrote them, or run it again. |
| `FAILS_BEFORE_DISPATCH` | permanent | The failed task failed before it ran, and nothing upstream of it would run again, so it would fail the same way. | Retry from a task upstream of it, or fix the Orkflow or its input and run it again. |

For `container_still_running`, cordon the named Orker and restart it ([DEPLOY.md](./DEPLOY.md#a-container-that-outlived-its-run), "A container that outlived its run"). For `child_runs_open`, end those runs. |
| `RESUME_CHECK_UNAVAILABLE` | wait | What a check needs (saved results, records, the cluster's list) did not answer, or, with `throttled`, the run's resume was confirmed too often in the last minute. | Try again after the time given; check object storage if it goes on. |
| `RELEASE_UNAVAILABLE` | wait | No engine of the release the run started on is running. | Start one, or run the run again. |
| `RERUN_POOL_UNSERVED` | wait | No Orker that can run the tasks again (or host their pin, or offer their profile) is live in their pool. | Start one. |
| `RESUME_IN_PROGRESS` | wait | A resume of the run was sent and is not settled. | Try again after the instant given. |
| `RESUME_UNCONFIRMED` | wait | The resume was sent. `reset_outcome_unknown`: its answer was lost, and whether it was applied will be known by the instant given. `not_carried_on`: it was applied and the run has not gone on yet. | Try again after the time given: a resume that was made is found, never made twice. For `not_carried_on`, check that the run's release is running. |
| `RUN_CHANGED` | replan | The run was resumed, reset or ended again since the caller looked. `resume_ended`: this resume was made, and its run could not carry the plan out, so it ended as before with nothing run again. | Preview again. |
| `PLAN_CHANGED` | replan | What would run again, or the highest stored event, has changed since the caller's preview. | Preview again. |
| `UNKNOWN_ATTEMPTS_NOT_ACKNOWLEDGED` | replan | An earlier attempt may still be running on an Orker that does not answer, and the confirm does not accept it. | Preview again, and accept each attempt it lists (`--acknowledge-unknown-attempts`) once it is safe to run beside it. |

## Force cancel

`ForceCancelRun` refuses a request with one of these reasons leading the message; nothing was started by it. A force cancel itself ends with a state, and where it stopped or lacks something, with one of the causes of the second table (`GetForceCancel`, and its `run.cancel.force.completed` audit record).

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `FORCE_CANCEL_GRACE_TOO_SHORT` | — | `invalid_argument`. The grace asked for is shorter than the run may need to end on its own cancel; the message names the least. Where the run's definition cannot be read, the least is `engine.runs.max_force_cancel_grace`. | Ask for at least that, or leave the grace out. |
| `FORCE_CANCEL_GRACE_TOO_LONG` | — | `invalid_argument`. The grace asked for is above `engine.runs.max_force_cancel_grace`, or above the least this run needs where that is more; the message names the most. | Ask for less, or leave the grace out. |
| `FORCE_CANCEL_REASON_TOO_LONG` | — | `invalid_argument`. The record the run's end would carry does not fit the cluster: the reason, the principal and what admitted them are too long together. | Give a shorter reason. |
| `no_signing_key` | — | `unavailable`. This engine cannot sign while the deployment verifies its callers, so it starts no force cancel; another engine may. | Restore its key file (`identity.key_files`), or make the request again for another engine to answer. |
| `FORCE_CANCEL_RETRIES_EXHAUSTED` | — | `failed_precondition`. Every try this request may make ended, too few of them given their whole time for the run to be ended directly, and the run is still open. | Read the run's audit records and the engines' logs for why they ended, then ask again under another `client_request_id`. |

| Cause | Category | Meaning | What to do |
|---|---|---|---|
| `decision_unverified` | — | Its decision did not verify: it was not made by this deployment, or not for this run. Nothing was done. | Make the request again. If it recurs, find out who starts workflows on the cluster. |
| `decision_stale` | — | The run was resumed since the decision was made, or the decision had expired. Nothing was done. | Make the request again. |
| `keys_unavailable` | — | The keys to verify the decision with could not be read. Nothing was done. | Restore the object store, then make the request again. |
| `audit_unwritable` | — | Nothing is signed here and the request could not be recorded, so nothing was done. | Restore the object store, then make the request again. |
| `record_too_large`, `text_refused` | — | The record the run's end would carry could not be made. The run was asked to cancel and not ended. | Give a shorter reason. |
| `clock_skew` | — | This engine's clock and the cluster's disagree on whether the grace has passed. The run was not ended. | Correct the clocks, then make the request again. |
| `run_kept_switching` | — | The run carried on in a newer generation each time it was ended. | Make the request again. |
| `retries_exhausted` | — | A step before the run was ended kept failing up to the ceiling. The run may still be open. | Read the engine's log, then make the request again. |
| `stopped`, `stopped_from_outside`, `timed_out`, `failed_unexpectedly` | — | It was stopped, terminated, ran out of its own time, or failed as it never should; the engine's log has the last. The run may have been ended first: then the force cancel reads as `force_canceled` and incomplete. | Make the request again: it finishes what is left. |
| `unknown_key`, `unverified_record` | — | The run closed with a record that does not verify here, under a key not known or by somebody else. | For a key, let the engines read the published keys again, then repeat the request. |
| `terminated_unclassified`, `event_sequence`, `event_unpublished` | — | The run was ended, and how it ended, or its ending's announcement, could not be completed. | Make the request again: it finishes what is left. |
| `not_below`, `chain_unreadable` | — | A run below that a cascade left alone: what started it, or the runs between, do not say it is below, or their records are gone from the cluster. | Force-cancel it by itself. |
| `id_occupied` | — | A run below whose force cancel could not be started: something else took each id tried. | Force-cancel it by itself, and find out who starts workflows on the cluster. |
| `too_many_runs`, `took_too_long`, `could_not_read` | — | Why a cascade could not confirm that nothing below is open. | Make the same request again with the cascade, from the tree's root where the tree is large. |

## The DSL at validate and create

These are refusals of an Orkflow document. They come from validate and create, when `uses:` values are resolved. A failed resolution is an error, never a silent fallback to a tag ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3").

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `UNKNOWN_ACTIVITY` | — | A bare `uses:` name is neither a catalog key nor an image reference, since it has no `/`, `:` or `@`. The message lists the catalog keys ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#42-the-activity-catalog-engine-config), "§4.2"). | Use one of the listed keys, or a full image reference. |
| `IMAGE_NOT_PINNED` | — (ContractViolation at the Orker) | A `uses:` value contains a template action. An image chosen at run time cannot be pinned at create. The Orker reports the same code, as a ContractViolation, if a task reaches it without a digest ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#42-the-activity-catalog-engine-config), "§4.2"). | Write `uses:` as a literal image reference or a catalog key. |
| `IMAGE_NOT_FOUND` | — | The registry answered 404 for the reference ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3"). | Check that the repository, and the tag or digest, exist in the registry that the reference names. |
| `IMAGE_RESOLVE_UNAUTHORIZED` | — | The registry refused the manifest request with 401 or 403 ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3"). | Check that the engine's registry credentials file, `ORK_REGISTRY_AUTH_FILE`, can read the repository ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#45-registry-credentials), "§4.5"). |
| `IMAGE_RESOLVE_UNAVAILABLE` | — | The registry answered with a server error, timed out, or could not be reached ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3"). | Create again once the registry answers. |
| `IMAGE_RESOLVE_UNSUPPORTED` | — | The reference does not parse (it is outside the distribution grammar: [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#42-the-activity-catalog-engine-config), "§4.2" rule 3), or the registry served a manifest or config that the resolver cannot read ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3"). | Use an image whose manifest and config the registry serves in a form that the resolver reads. |
| `IMAGE_DIGEST_MISMATCH` | — (ContractViolation at the Orker) | The bytes that the registry served do not hash to the digest they were addressed by. This covers a pinned reference, a platform manifest, the config blob, and the content-digest header the registry sends. The Orker reports the same code, as a ContractViolation, when a pulled image does not match its pin ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#43-where-resolution-runs), "§4.3"). | Check the digest against the registry, and check that nothing between the engine and the registry rewrites responses. Apply does not fall back to a tag, so the reference stays unpinned until it resolves to a digest that verifies. |

## Evidence bundles

A member of an evidence bundle that is reclaimed, unrecorded, rejected or withheld carries one of seven lowercase tokens as its `reason`. `orkctl run evidence verify` reports each one as a finding, not a failure, and exits 0 for it ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#verify), "verify").

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `definition_deleted` | — | The pinned definition was deleted from the Orkflow store. The run's definition digest still attests it ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | Nothing to repair in the bundle. `verify` lists the definition as reclaimed, with its recorded digest kept. |
| `definition_not_readable` | — | The run is a child run of another namespace's shared Orkflow, and whoever exported the bundle may not read that Orkflow there. The bundle carries no bytes for it; the run's definition digest still attests it ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the definition as withheld. To include it, export the bundle as someone with `orkflow.read` on the Orkflow in its owner's namespace. |
| `definition_digest_mismatch` | — | A document exists at the run's pinned coordinates, but it does not hash to the digest the run pinned. The bundle carries no bytes for it, and records the document's own digest ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the definition as rejected. Compare the stored digest with the run's pinned digest, both of which the bundle records. |
| `commit_missing` | — | The commit record was reclaimed by cleanup. Its recorded digest is preserved ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the commit as reclaimed. Nothing to repair in the bundle. |
| `object_missing` | — | The object was removed from the store by a lifecycle rule or by cleanup. Its recorded digest is preserved ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the object as reclaimed. If the object should have been kept, check the bucket's lifecycle rules. |
| `artifact_reclaimed` | — | The artifact GC deleted the object after its run was retired. Its recorded digest is preserved ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the object as reclaimed. Nothing to repair in the bundle. |
| `attempt_record_missing` | — | No attempt record exists, because the Orker died before filing one or cleanup reclaimed it ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the attempt as unrecorded. The other attempts' records and logs are unaffected. |

Otherwise each attempt records its HTTP status, which is 0 when the request never completed, and the transport error, if there was one. | Reason | Category | Meaning | What to do |
|---|---|---|---|
| `WEBHOOK_DESTINATION_BLOCKED` | — | The webhook's destination is a loopback, link-local, private, shared, multicast or otherwise non-public address. Registration refuses a URL whose host is one (`invalid_argument`). A delivery attempt that would connect to one fails with this reason at the start of its error, whether the address came from a name or from a redirect, and is not retried ([WEBHOOKS.md](./WEBHOOKS.md#where-a-delivery-may-go), "Where a delivery may go"). | List the receiver's network in `webhooks.allowed_networks` (`ORK_WEBHOOK_ALLOWED_NETWORKS`), or point the webhook at a public address ([DEPLOY.md](./DEPLOY.md), § 1). |

| `EVENT_SOURCE_INVALID` | — | The source breaks a bound or a rule of its own document, before anything else is read; names the field. | Fix the field. |
| `EVENT_SOURCE_LIMIT` | — | A quota or a sum is full: sources per deployment or namespace, instances, or a namespace's rate; the refusal carries the arithmetic. | Delete a source, lower a number, or raise the setting. |

| `EVENT_SOURCE_IMAGE_UNSUPPORTED` | — | The image is not a source image this release hosts (`SERVICE_CONTRACT_UNSUPPORTED`, `SERVICE_PROFILE_UNSUPPORTED`), declares its interface wrongly, or `uses:` names a first-party image, none of which ships with this release. | Name an image of the event-source profile by its registry reference. |
| `SERVICE_CONTRACT_UNSUPPORTED` | — | Carried by `EVENT_SOURCE_IMAGE_UNSUPPORTED`: the image implements no Orker Service Contract version this release hosts, or carries no `org.orkstack.service.contract` label. | Use an image built for contract version 1 ([EVENT_SOURCES.md](./EVENT_SOURCES.md#the-image), "The image"). |

| `EVENT_SOURCE_ORKFLOW_UNSUPPORTED` | — | The Orkflow declares something a run started by a message cannot be given: an await with `callback: true`, or tasks that ask for identities or credentials. | Bind another Orkflow. |
| `EVENT_SOURCE_IDENTITY_UNSUPPORTED` | — | The source declares its own identities, credentials or a secret through a grant, which need task identity. | Use `env:` or `file:` secrets the namespace allows. |
| `EVENT_SOURCE_NAMESPACE_MISMATCH` | — | An update's source names another Orkflow than the stored one, or `orkctl`'s `-n` names another namespace than its file; both are named and nothing was written. | Send it in the source's own namespace, or correct the file. |
| `EVENT_SOURCE_ID_MISMATCH` | — | A delete named a source by an id the name no longer holds; the text names the id it holds now, and nothing was deleted. | Look at the source the name holds now (`orkctl event-source get`). |
| `EVENT_SOURCE_DOCUMENT_UNREADABLE` | — | A stored source was written by a release this engine cannot read; nothing of it is answered. | Ask an engine of the release that wrote it. |
| `EVENT_SOURCE_PAUSED` | — | The state of a source an operator paused. | `orkctl event-source resume`. |
| `EVENT_SOURCE_NOT_CONVERGED` | — | The state of a stored source that runs nothing; in this release no source runs. | Nothing. |

| `MESSAGE_UNPROCESSABLE` | — | The source's selectors could not be read. | Fix the selector it names. |
| `MESSAGE_DELIVERIES_EXHAUSTED` | — | A message was not accepted at its broker's delivery limit and was given back for the broker to dead-letter; the receipt's cause says why it was refused or what it waited for. | Look at the broker's dead-letter queue, and at the cause. |
| `MESSAGE_RELEASED_HOLD_EXPIRED` | — | No verdict came within the message's hold bound, and its container released it for another delivery; a fault of the Orker, counted. | Check the Orker hosting the instance. |
| `MESSAGE_RELEASED_ACCEPT_FAILING` | — | The instance was waiting (the engine, admission, a pool or the store would not let the message start) and gave the message back for another delivery; nothing was wrong with it. The receipt's cause names the wait. | Look at the source's status: it reads `WAITING` with the cause. |

### Service attempts

An Orker ends one attempt of a service container with one of these. The owner (for an event source, its workflow) decides what follows; "retried" is the attempt's default.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `SERVICE_EXITED` | retried | The container exited `0` when nobody asked it to stop. | Keep the service running until it is stopped. |
| `SERVICE_FAILED` | retried | The container exited non-zero when nobody asked it to stop; carries the code. | Read the instance's logs. |
| `SERVICE_OOM_KILLED` | retried | The container was killed for memory; its `answer/` filesystem counts against its memory. | Raise `resources.memory`. |
| `SERVICE_NOT_READY` | retried | The container wrote no `status.json` within its `startupSeconds`. | Write a status as soon as the image can say anything. |
| `SERVICE_CONFIG_REJECTED` | not retried | The container's status said `fatal`: it can never work with this configuration; carries its `check.reason` and `check.field`. | Fix the setting it names. |
| `SERVICE_UNRESPONSIVE` | retried | More than a quarter of its lanes, and at least one, stayed waiting for a step past twice its deadline, or a lane past the longest hold; or one lane had three late exchanges in a row. | Answer each step within its deadline. |

| `SERVICE_CONTRACT_VIOLATION` | not retried | The container broke the contract: a link, device, FIFO, socket, directory or file with two names at a name the Orker reads, a file over its bound, a step out of sequence, or a malformed file. | Fix the image ([ORKER_SERVICE_CONTRACT.md](./ORKER_SERVICE_CONTRACT.md)). |
| `SERVICE_STOP_STUCK` | — | The container was not gone a minute after its SIGKILL. The attempt is ended so its owner can go on; the Orker keeps trying to remove it, keeps its reservation, and takes no further service until it is gone. | Check the container runtime on that host. |
| `SERVICE_RUNS_AS_ROOT` | retried | The image declares the root user and ended before its first status. A service container runs as an arbitrary non-root uid (the Orker's own), so an image that needs root cannot work. | Build the image to run as any non-root user ([ORKER_SERVICE_CONTRACT.md](./ORKER_SERVICE_CONTRACT.md)). |

## Pause warnings

A paused run tells each running child run of its pause. Each reason below is one way that did not happen, recorded on the parent run (`Run.pause_warnings`) while it stays paused and noted on the composed task. The child keeps running, so the category is a dash.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `CHILD_NOT_PAUSABLE` | — | The child run was started without support for pausing, so it was not told. | None needed, or pause the child run itself once it supports pausing. |
| `CHILD_PAUSE_FAILED` | — | The pause could not be delivered to the child run after its retries. The message carries the error. The next pause or unpause tries again. | Read the message. Pause the child run itself if it must stop starting work. |
