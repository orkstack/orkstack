# Error reasons

Every terminal failure and every refusal carries a machine-readable reason and a human-readable message (AGENTS.md §15). This page has one row for each reason that the code declares as a named constant in `internal/task`, `internal/orker`, `internal/engine`, `internal/dsl` and `internal/authz`. It also has rows for the reasons that the engine writes inline as string literals, such as `RUN_FAILED`, and for the lowercase evidence tokens. Each reason is spelled exactly as the code spells it, so a client can match on it.

Event types, the `Event*` constants in `pkg/webhooks`, are not failure reasons and are not listed.

The **Category** column is the failure category the code assigns (see [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). Retry follows the category: `ActivityFailed` and `InfrastructureError` are retried under the task's `retry:` policy, and `ContractViolation`, `TimedOut` and `Cancelled` are not. Where a row states a retry outcome, the code or the contract states it. A dash means the code carries no failure category. Most dashes are refusals or cache misses, and `PANIC` is recorded but never reported as a reason.

## Submit and admission

A refusal here happens before a run ID is minted and before an idempotency key is claimed, so a refused submission leaves nothing behind ([DEPLOY.md](./DEPLOY.md#namespace-admission-hold-and-max_running), "Namespace admission"). The image policy is checked again at create, and by the Orker when a task is dispatched.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `NAMESPACE_HELD` | — | The namespace is on hold, so it accepts no new runs. A run accepted before the hold is not affected ([DEPLOY.md](./DEPLOY.md#namespace-admission-hold-and-max_running), "Namespace admission"). | Submit again after the hold is released with `orkctl namespace update NS --release-hold`. Releasing a hold starts nothing that was refused while it was set. |
| `MAX_RUNNING_REACHED` | — | The namespace already has as many runs in flight as its `max_running` cap. The count comes from the cluster's execution index at submit ([DEPLOY.md](./DEPLOY.md#namespace-admission-hold-and-max_running), "Namespace admission"). | Wait for a run to finish and submit again, or raise the cap with `orkctl namespace update NS --max-running N`. |
| `BUDGET_EXCEEDED` | — | An enforced budget is at or above its bound for cpu-seconds or GiB-seconds over its trailing period. Accepted runs are not touched ([DEPLOY.md](./DEPLOY.md#namespace-budgets-reserved-consumption-soft-or-enforced), "Namespace budgets"). | New runs are refused until the period's usage falls below the budget. Raise the budget with `--budget-cpu-seconds` or `--budget-gib-seconds` on `orkctl namespace update`, or stop enforcing it with `--budget-enforce=false`. |
| `BUDGET_UNMEASURABLE` | — | An enforced budget cannot be measured. The period holds more finished runs than a usage read covers, or no archive or attempt store is configured ([DEPLOY.md](./DEPLOY.md#namespace-budgets-reserved-consumption-soft-or-enforced), "Namespace budgets"). | Shorten the period with `orkctl namespace update NS --budget-period D`, or stop enforcing with `--budget-enforce=false`. First check that `orkctl stats usage -s PERIOD` answers. A read that merely failed is reported as unavailable, so ask again. |
| `IMAGE_NOT_PERMITTED` | ContractViolation, not retried | The image is outside the run's image policy. It is a mutable tag where the policy requires a digest, a registry outside its allow-list, or a signer with no usable key ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#47-image-policy-at-the-orker), "§4.7"). | Use an image by digest from a registry the policy allows. The operator sets the policy floor ([DEPLOY.md](./DEPLOY.md#image-supply-chain-policy), "Image supply-chain policy"). |
| `IMAGE_NOT_SIGNED` | ContractViolation, not retried | The namespace requires a signature, and the registry has none for this digest ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#47-image-policy-at-the-orker), "§4.7"). | Sign the image digest with a key that the policy names ([DEPLOY.md](./DEPLOY.md#image-supply-chain-policy), "Image supply-chain policy"). |
| `IMAGE_SIGNATURE_INVALID` | ContractViolation, not retried | Signatures exist for the digest, but none verifies with the named key over that digest ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#47-image-policy-at-the-orker), "§4.7"). | Sign the digest with the key that the policy names. A signature from another key, or over another digest, does not count. |
| `IMAGE_SIGNATURE_UNAVAILABLE` | InfrastructureError, retried | The registry could not be asked for the signature, or the Orker has no registry client. This is never a pass. At create and at submit the refusal is `unavailable` rather than this code ([DEPLOY.md](./DEPLOY.md#image-supply-chain-policy), "Image supply-chain policy"). | Retried under the task's policy. If it persists, check that the registry is reachable and that the registry credentials file is set: `ORK_REGISTRY_AUTH_FILE` for the engine, `ORK_ORKER_REGISTRY_AUTH_FILE` for the Orker. |
| `RESOURCES_UNSATISFIABLE` | — | A task asks for more cpu, memory or gpu units than the per-task cap of every Orker of its pool that answered (`orker.resources.max_cpu`, `max_memory`, `max_gpu`), so no Orker there could ever run it: an Orker refuses such a request after dispatch, terminally. It is refused at submit, and `allow_empty_pool` does not change that. An Orker that reports no cap, or a pool none of whose Orkers answered, is logged and not refused ([DEPLOY.md](./DEPLOY.md#declaring-an-orkers-capacity), "Declaring an Orker's capacity"). | Ask for less, or run the task on a pool whose Orkers set larger caps. |
| `PROFILE_UNAVAILABLE` | — | A task names a profile in `devices:` that an Orker of its pool does not offer, or no Orker of the pool answered, so no Orker is known to offer it; or the task's image needs a contract of the profile that an Orker of the pool neither owns nor accepts, which the refusal names with the Orker. Every Orker of a pool may take the task, so every one must serve it. It is refused at submit, and `allow_empty_pool` does not change that ([DEPLOY.md](./DEPLOY.md#changing-a-profile), "Changing a profile"). | Define the profile, with the contract the image needs, on every Orker of the pool, or start one that does, and submit again. |
| `PROFILE_MISMATCH` | — | Two Orkers of a task's pool define a profile it names differently: as another kind, or one contract label with other devices, which the refusal names with the two Orkers; or, for a task whose image declares no contract, the Orkers' default contracts serve no one label between them, which the refusal lists. It is refused at submit ([DEPLOY.md](./DEPLOY.md#changing-a-profile), "Changing a profile"). | Give a changed definition a new contract label, never the old one; add the old label to the new default's `accepts:`, or finish rolling the pool. |
| `ORKFLOW_NOT_SHARED` | — | A composed task names another namespace's Orkflow whose pinned version's `shared_with:` does not admit the composing Orkflow. It is refused at validate and create, on the composed task's `uses:`, and again at every submit that plans the child, at any depth ([DSL.md](./DSL.md#sharing-across-namespaces), "Sharing across namespaces"). | The owner adds `namespace: <caller namespace>` or `orkflow: <caller namespace>/<caller name>` to `shared_with:` in a new version, and the caller pins that version. |
| `FOREIGN_SECRETS_UNBOUNDED` | — | A shared Orkflow composed from another namespace names a secret, and the namespace it runs in sets no `allowed_secrets`, which leaves only its own Orkflows unrestricted ([DSL.md](./DSL.md#sharing-across-namespaces), "Sharing across namespaces"). | List the sources the namespace may read with `orkctl namespace update NS --allow-secret PATTERN`. The shared Orkflow is then held to that list. |
| `SHARED_ORKFLOW_NOT_ROOT` | — | Run again names a child run of another namespace's shared Orkflow. Such an Orkflow runs only as a child, never as a root run ([DSL.md](./DSL.md#sharing-across-namespaces), "Sharing across namespaces"). | Run its root run again; the message names it. |
| `CONCURRENCY_KEY_INVALID` | — | A concurrency limit's key breaks the key rule (1 to 128 bytes of letters, digits and `. _ : / @ + = -`, starting with a letter or digit, not `ork:`), or its template did not render, such as an input it reads that the run does not have. A literal key is refused at validate, a rendered one at submit (`INVALID_ARGUMENT`), naming the template and the first bad byte ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). | Fix the key template, or submit with the input it reads. |
| `CONCURRENCY_UNSUPPORTED` | — | The Orkflow declares a concurrency limit this deployment cannot hold. `cause=index`: the cluster does not index the attributes a limit is kept by. `cause=fleet`: an engine process runs a release without concurrency limits (`concurrency-1`). Or the limit is declared by an Orkflow that would run as a composed child, which this release does not hold ([DEPLOY.md](./DEPLOY.md), "Which capabilities exist"). Refused `UNAVAILABLE` when a rollout is the only cause, else `FAILED_PRECONDITION`; create and validate store the Orkflow and warn. | Finish the rollout to one release, or let the engine add the search attributes. Submit a limited Orkflow as a run of its own. |
| `CONCURRENCY_QUEUE_FULL` | — | The run would wait in a concurrency limit's line, and that line is full: `cause=max_queued` (the limit's own `max_queued`), `cause=max_entries` (the most one key holds, `engine.concurrency.max_entries`), or `cause=namespace` (the namespace's queued runs, `engine.concurrency.max_queued_runs_per_namespace`). Refused `RESOURCE_EXHAUSTED` at submit; the count is best-effort ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). | Submit again later, or cancel queued runs you do not need. |
| `CONCURRENCY_KEYS_EXHAUSTED` | — | The run's key is new and the namespace already has as many keys with runs holding or queued as it may (`engine.concurrency.max_active_keys_per_namespace`). Refused `RESOURCE_EXHAUSTED` at submit, best-effort. | Submit again once a key is free, or render fewer distinct keys. |
| `CONCURRENCY_CHECK_UNAVAILABLE` | — | Whether the run's concurrency limit can be held, or would fit, could not be checked: the cluster's list of engine processes (`scope=fleet`), the key's line (`scope=key`) or the namespace's counts (`scope=namespace`) could not be read. The submit is refused `UNAVAILABLE` and leaves nothing behind. | Submit again. |
| `INPUT_TOO_LARGE` | ContractViolation | The run's input is over 256 KiB, so it is refused at submit and at a schedule's fire. The same code is raised when a task's input would exceed the limit at dispatch ([DSL.md](./DSL.md#inputs), "Inputs"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Pass a reference to large data, such as a URL or an object key, instead of its bytes. A deep chain that fails at dispatch is split into composed Orkflows ([DSL.md](./DSL.md#how-many-tasks-an-orkflow-may-declare), "How many tasks an Orkflow may declare"). |

## Authorization

With `auth.mode` `observe` or `enforce`, a request is decided against the access document before any handler runs ([ACCESS.md](./ACCESS.md#how-a-request-is-decided), "How a request is decided"). In `enforce` mode these refuse the request; in `observe` mode they are recorded as `would-deny` and the request is served. A run the caller may not read is answered `not_found` instead, as one that does not exist.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `PERMISSION_DENIED` | — | No binding grants the caller the permission at a scope that covers what the request names. The message names the caller, the permission and the scope, and never a binding ([ACCESS.md](./ACCESS.md#permissions), "Permissions"). | Ask an administrator for a binding of a role that holds the permission, at that scope or a wider one. A list paged by a key walk names the filter to add instead. |
| `PRINCIPAL_DISABLED` | — | The caller's id is under `disabled` in the access document, so it is refused whatever it presents, and its open streams are closed ([ACCESS.md](./ACCESS.md#subjects), "Subjects"). | An administrator enables the principal again, or the caller stops using it. |
| `UNAUTHENTICATED` | — | The request carries no verified caller, where the permission needs one ([AUTHENTICATION.md](./AUTHENTICATION.md#what-the-api-accepts), "What the API accepts"). | Send `Authorization: Bearer` with a token from a trusted issuer. |

## The Orker and the container

The Orker runs each task attempt, and an attempt reports at most one of these reasons. Seven are boot refusals, marked below: the Orker refuses to start, so no task carries them. `RUN_AS_ORKER_UNAVAILABLE` is a task failure, and a boot refusal only on an Orker that runs every task as its own user.

### Container, image and workspace

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `CONTAINER_EXIT_NONZERO` | ActivityFailed, retried | The container exited non-zero. Every non-zero status gives this reason, whatever the number. The message says when the kernel killed the container at its memory limit ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the attempt's stderr. The exit status alone does not say what failed. |
| `CONTAINER_TIMEOUT` | TimedOut, not retried | The Orker stopped the container when the task's `timeout_seconds` ran out: SIGTERM, then SIGKILL after the grace period ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the attempt's stderr to see how far the run got. Raise `timeout_seconds` if the work legitimately takes longer. A timeout is not retried, because it would hit the same limit again ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). |
| `RUNTIME_REFUSED` | InfrastructureError, retried | The container runtime returned an error from create or start, so the container never ran, or from waiting on it, because its daemon went away ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Retried. If it recurs, the fault is on the Orker's host, not in the workload. |
| `CONTAINER_STOPPED_BY_RUNTIME` | InfrastructureError, retried | The container ran, and something stopped it through its runtime before it ended: its daemon shut down or restarted, or someone stopped or killed it. Its exit code says nothing about the workload, and its output is not committed ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | While its Orker is stopping, it runs again within its run's hand-back budget ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"); otherwise it is retried under the task's `retry:`, so a task with none fails here: submit it again. If nothing on the host explains it, check who is stopping containers on the Orker's daemon. |
| `WORKSPACE_NOT_BINDABLE` | InfrastructureError, not retried | The container runtime cannot bind the attempt's workspace path. This is a host misconfiguration, and a retry would fail the same way ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#31-layout), "§3.1"). | Make `ORK_ORKER_WORKDIR` a path that the container runtime can bind-mount. |
| `WORKDIR_NOT_BINDABLE` | InfrastructureError, not retried. Boot refusal. | `ORK_ORKER_WORKDIR`'s path holds a comma or control character, which a container mount cannot carry, or the container daemon refused the boot probe's bind within its budget in its own words, or the probe's container did not read back the nonce the Orker wrote into the bind, or the Orker did not read back the one the container wrote (the daemon bound a directory of its own, as a daemon that does not share the Orker's filesystem does), or no probe directory could be created: `ORK_ORKER_WORKDIR` cannot be bind-mounted, so the Orker refuses to start. The message carries what the daemon said, or which nonce did not arrive. A probe container the Orker could not remove is named in the refusal or logged. A daemon that was only slow, including one that answered with a deadline error of its own, is `BIND_PROBE_TIMED_OUT` instead ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#31-layout), "§3.1"). | Point `ORK_ORKER_WORKDIR` at a path that the container runtime can bind-mount, then start the Orker. |
| `RUNTIME_POSTURE_REFUSED` | InfrastructureError. Boot refusal. | The boot probe runs one container built exactly as a task's is, and the container runtime did not give it a task's posture. `ORK_DOCKER_CLI` names no CLI, or the engine behind the CLI could not be identified (a daemon that cannot be reached, quoted in its own words, or the podman CLI under the name `docker`, which the message says to set `ORK_DOCKER_CLI=podman` for), or the runtime refused the container for a reason that is neither a bind nor a deadline, or the container exited non-zero, or what it saw from inside was weaker: privileges it could gain, no seccomp filter, a capability, a writable root, `/run`, `/var/tmp` or input, a `/tmp` without `noexec`, a proxy variable it was never given, or cgroup v2 limits other than it asked for. The message names each, and a proxy variable by name only. A probe container the Orker could not remove is named in the refusal or logged ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#31-layout), "§3.1"). It also covers a second container built the same way, whose workload traps SIGTERM and is cancelled as a task is, when that workload never heard SIGTERM: every cancelled task would be killed at the end of its grace without its cleanup. That message quotes the security label and the signal masks the workload ran with. | Fix the runtime so that it applies what it is asked for. For a workload that never heard SIGTERM under a stacked AppArmor label, as on rootful Podman under AppArmor 5, add the rule [DEPLOY.md](./DEPLOY.md#rootful-podman-under-apparmor) gives, or run Podman rootless. For a proxy variable, remove the proxy configuration of the container CLI the Orker drives (for the docker CLI, `proxies` in its `config.json`); a task that needs a proxy sets it in its own `env:`. For limits on a rootless runtime, delegate the `cpu`, `memory` and `pids` controllers to its user. Then start the Orker. |
| `BIND_PROBE_IMAGE_UNAVAILABLE` | InfrastructureError. Boot refusal. | The boot probe's own image, alpine 3.24 by digest (`docker.io/library/alpine:3.24@sha256:f59abe656b692d901e184be3445e084786602108599d2a51d229c0f5a48c71bf`), is not present on the Orker and could not be pulled within the pull timeout. The Orker refuses to start, and the reason names the image rather than the work root ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Make the image available to the Orker, and raise the pull timeout if the pull is slow ([DEPLOY.md](./DEPLOY.md#1-configuration), "§1"). Then start the Orker. |
| `BIND_PROBE_TIMED_OUT` | InfrastructureError. Boot refusal. | The container daemon was too slow for the boot probe. It did not say within the bind probe timeout which engine it is and whether it is rootless, or whether the probe's image is local, or on each of two attempts it did not start one of the probe's two containers within the timeout or ended the attempt with a deadline error of its own, or the second container's workload, the one that traps SIGTERM, did not say it was ready within it. That says the daemon is slow or unresponsive and nothing about whether `ORK_ORKER_WORKDIR` can be bind-mounted, so the Orker refuses to start without calling the work root unbindable. The message quotes what the daemon answered. A probe container the Orker could not remove is named in the refusal or logged ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#31-layout), "§3.1"). | Check that the container daemon is healthy and not overloaded, for example that `docker run --rm docker.io/library/alpine:3.24@sha256:f59abe656b692d901e184be3445e084786602108599d2a51d229c0f5a48c71bf true` finishes. Raise the bind probe timeout if the daemon is only slow ([DEPLOY.md](./DEPLOY.md#1-configuration), "§1"). Then start the Orker. |
| `METADATA_ENDPOINT_REACHABLE` | InfrastructureError. Boot refusal under `orker.metadata_probe: refuse`. | The metadata probe ran a container built as a task's is on the `default` network, and an instance metadata endpoint answered it: a task on this host could ask that endpoint for the host's role. The message names each address that answered and the request it answered, such as `169.254.169.254 (HTTP 200 to PUT /latest/api/token)`, and never what the endpoint sent ([DEPLOY.md](./DEPLOY.md#keeping-tasks-away-from-the-hosts-identity), "Keeping tasks away from the host's identity"). | Close the endpoint to containers on the host, as that section's table says for the platform: on EC2, require IMDSv2 with a hop limit of 1. Then start the Orker. `orker.metadata_probe: warn` starts it anyway and logs what answered. |
| `METADATA_PROBE_FAILED` | InfrastructureError. Boot refusal under `orker.metadata_probe: refuse`. | The metadata probe could not tell whether an endpoint answers: its container did not run, its image was missing, the runtime refused it, or it ended before it reported every request. A probe that failed is never read as safe. The message names each address and why ([DEPLOY.md](./DEPLOY.md#keeping-tasks-away-from-the-hosts-identity), "Keeping tasks away from the host's identity"). | Fix what the message names, for example a `default` network the runtime cannot attach, then start the Orker. |
| `RUN_AS_ORKER_UNAVAILABLE` | InfrastructureError, not retried. Boot refusal under `ORK_ORKER_FORCE_USER`. | The task runs as the Orker's own user, because it sets `run_as_orker_user: true` or the Orker sets `ORK_ORKER_FORCE_USER`, and the boot probe found that this user does not land as the Orker on this host: a `0600` file its container wrote as the Orker's user is one the Orker cannot read. A rootless or user-namespaced daemon maps the Orker's uid to another host user, so the escape hatch would not make the workload's files readable. The task fails before a container is created; an Orker that runs every task that way refuses to start ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#31-layout), "§3.1"). | Run the Orker as root inside the runtime, or on a daemon without a user namespace, or make the image write readable files (`umask 022`) and drop `run_as_orker_user`. |
| `WORKDIR_FAILED` | InfrastructureError, retried | The attempt's directory, a pin's directory, or an input file could not be created, or the Orker had no file descriptor left to hold an output artifact open ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Retried. If it persists, check that the Orker's work root is writable and that its open-file limit covers its concurrent attempts' `artifact_max_count`. |
| `IMAGE_PULL_FAILED` | InfrastructureError, retried | The pull failed or timed out, and the Orker has no verified copy of the image ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Retried. If it persists, check that the Orker can reach the registry and that the pinned digest exists there. The pull timeout is in [DEPLOY.md](./DEPLOY.md#1-configuration), "§1". |
| `PANIC` | — | Not reported to a run. The Orker's attempt observer and its per-reason metrics record it when an attempt unwinds by a panic. The task's failure reaches the engine through the workers' own error path ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Nothing for a client to do. |

### Values, artifacts and outputs

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `VALUES_MISSING` | ContractViolation, not retried | The container exited 0 but wrote no `output/values.json` ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#34-outputvaluesjson), "§3.4"). | Write a result. A workload with no result writes `{}`. |
| `VALUES_MALFORMED` | ContractViolation, not retried | `values.json` is not UTF-8 JSON, or an object in it writes a key twice (the message names the key and the object), or its top level is not an object, or it is not a regular file: a symlink (whatever its target), a directory, a device, a socket or a FIFO. The Orker follows no link the workload wrote ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#34-outputvaluesjson), "§3.4"; "§9.5"). | Write a JSON object at the top level, each key once, as a regular file. |
| `VALUES_TOO_LARGE` | ContractViolation, not retried | `values.json` is over the values limit, 256 KiB by default ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#34-outputvaluesjson), "§3.4"). | Write less. A larger result is an artifact. |
| `VALUES_CONTAIN_SECRET` | ContractViolation, not retried | `values.json` holds the value of one of the task's own secrets; the message names the secret and where by position, never the value, and nothing was uploaded ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#94-secrets), "§9.4"). | Return a reference to the secret, not its value. Set `mask: false` only on a secret that is configuration. |
| `MASK_CAPACITY_EXCEEDED` | ContractViolation, not retried | The task's secrets have more masking forms than one masker holds, so the container was not started; the message names the largest secrets by name and size ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#36-streams), "§3.6"). | Give the task fewer or smaller secrets, or set `mask: false` on one that is configuration. |
| `VALUES_CORRUPT` | ContractViolation, not retried | When a retry adopts an existing commit, the `values.json` fetched from storage does not match the digest the commit recorded ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#54-the-sequence), "§5.4"). | Not retried, because the stored result is not what was committed. Read the message and check the object store. |

| `ARTIFACT_NOT_A_FILE` | ContractViolation, not retried | An entry directly in `output/artifacts/` is a directory, symlink, device, socket or FIFO, or `output/artifacts` itself was replaced by a symlink, a file or anything else that is not a directory. | `COMMIT_WRITE_FAILED` | InfrastructureError, retried | A conditional write of the commit failed for a reason other than the object already existing. | `COMMIT_SCHEMA_UNSUPPORTED` | ContractViolation, not retried | An existing commit has a `schema_version` that this Orker does not read. | `COMMIT_IDENTITY_MISMATCH` | ContractViolation, not retried | An existing commit at this key differs from this attempt on one of seven identity fields. ## The engine and the run

These codes come from the engine: how a run starts and ends, its tasks, its history, joins, pins, awaits, fan-out, composed tasks, declared outputs, routing and plan simulation. A composed task is never retried, and an awaited task has no retries ([DSL.md](./DSL.md#composition-uses-orkflow), "Composition"; [DSL.md](./DSL.md#awaited-tasks), "Awaited tasks").

### Run start

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_START_FAILED` | — (status `FAILED`) | The run's start failed after its run ID was minted. The run is recorded FAILED with no task, pool, Orker, image or phase, and its message is the cause ([STATS.md](./STATS.md#6-failure-fingerprints), "§6"). | Read the message. No task ran, so there is nothing to cancel. Submit the run again. |
| `INVALID_RUN` | — | The run's start refused a run with no run ID, with the message "run id is required". A client sees `RUN_FAILED` with that message, except for a run carried on by an older release, which reads as `RUN_STATE_UNSUPPORTED` ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Nothing for a client to act on. The submit path mints the run ID before the run starts (AGENTS.md §7). |
| `INVALID_ORKFLOW` | — | The run's start refused an Orkflow with no tasks, with the message "orkflow has no tasks". A client sees `RUN_FAILED` with that message ([DSL.md](./DSL.md#top-level-fields), "Top-level fields"). | Add at least one task to the Orkflow, then apply it again. |

### Run outcomes

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_FAILED` | — (the failing task's category applies) | The run failed. Its message is the cause, and its details name the failing task (`task "<id>"`). A fan-out's or a composed task's failure carries that node's sentence. | `RUN_CANCELED` | — (status `CANCELED`) | The run was cancelled, so its status is `CANCELED` and its message is "run canceled" ([CLI.md](./CLI.md#orkctl-run-cancel), "orkctl run cancel"). | `RUN_TERMINATED` | — (status `CANCELED`) | The run was ended from outside its own execution. Its message is the termination reason, or "run terminated" when none was given. A cluster end at the run's history limit is reported as `RUN_HISTORY_LIMIT` instead ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message for the reason. Start a new run if the work is still needed. |
| `RUN_RECORD_INCOMPLETE` | InfrastructureError, keeps the run's status | The run's archive was built from its history and the record of its tasks could not be recovered from object storage. Check for a bucket lifecycle rule over `metadata/snapshots/`, which must not exist. |
| `RUN_TIMED_OUT` | TimedOut (status `FAILED`) for a run's own timeout; — for a cluster limit | Two causes. Or the cluster ended the run's execution at a time limit set outside the run's start, with the message "run timed out" and no category. | For the run's own timeout, raise `timeout:` in a new version of the Orkflow and run it again. For a cluster limit, start a new run if the work is still needed. |
| `RUN_DEFINITION_UNSUPPORTED` | ContractViolation, not retried | The run's definition declares a feature its plan does not carry, such as a run timeout submitted through a release that did not plan one. The run ends at its first step, after `RUN_CREATED` ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). | Submit the run again once every engine process runs the same release. |
| `RUN_TIMEOUT_STATE_INVALID` | ContractViolation, not retried | The run declares a run timeout but its clock was never started, a state the engine never writes. It ends explicitly rather than run with no deadline ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). | Run it again. Report it if it happens again. |
| `RUN_PAUSE_TIMEOUT` | TimedOut (status `FAILED`) | The run was paused and not unpaused before its pause timed out, or the parent run whose pause held it neither unpaused it nor ended before its backstop. | `RUN_CONCURRENCY_LIMIT` | — (status `FAILED`) | The run's concurrency limit refuses a run when every slot of its key is held, and every slot was ([DSL.md](./DSL.md#concurrency-limits-concurrency), "Concurrency limits"). | `RUN_CONCURRENCY_FULL` | — (status `FAILED`) | The line for the run's key was full: it already held as many runs as the deployment allows one key (`engine.concurrency.max_entries`). | Submit the run again later, or raise `engine.concurrency.max_entries`. |
| `RUN_CONCURRENCY_UNAVAILABLE` | InfrastructureError (status `FAILED`) | The run's concurrency limit did not answer within `engine.concurrency.acquire_timeout`, or was still rebuilding its record of running runs when the run's wait ended. | Submit the run again. If it recurs, check the engine's logs for the limit, and the `ork.concurrency.rebuilding` gauge. |
| `RUN_CONCURRENCY_FENCED` | ContractViolation, not retried | The run's concurrency limit refused a request from this run as stale or already released: a clock far behind the engine's, or a request sent again after the run let the slot go. | Submit the run again. If it recurs, check the engine hosts' clocks. |
| `RUN_CONCURRENCY_UNSUPPORTED` | ContractViolation, not retried | The run's concurrency limit could not take its request (`cause=protocol`): the engine that keeps the limit runs a release that does not support it. | Finish rolling the deployment out to one release, then submit the run again. |
| `RUN_QUEUE_TIMEOUT` | TimedOut (status `FAILED`) | The run waited in line for its key for its limit's `queue_timeout` and was never given a slot. The message names the key and how long it waited. | Submit the run again; or raise `queue_timeout`, or the limit. |
| `RUN_SUPERSEDED` | Cancelled (status `CANCELED`) | Another run of the same key replaced this one while it waited, by its limit's strategy. The message names that run. | Nothing to do: the run that replaced it does the work. |

### Task outcomes

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `TASK_FAILED` | The error's category, if it has one | The default code for a task failure that carries no reason of its own. Its message holds the cause ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message. |
| `TASK_STOPPED_BY_RUN_TIMEOUT` | TimedOut, not retried | The task was running, waiting or sleeping when its run's own `timeout:` passed, so it was stopped and recorded `FAILED`. A fan-out with an item stopped this way, and a composed task whose child run was stopped, carry the same code. `join: any_failed` handlers see it as a failure ([DSL.md](./DSL.md#run-timeout-timeout), "Run timeout"). | Raise `timeout:` in a new version of the Orkflow, or make the task faster. |
| `TASK_CANCELED` | Cancelled | The task was cancelled. Its status is `CANCELED`, so it did not fail, and it is not retried automatically ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). | Start a new run if the work is still needed. |
| `TASK_OUTPUT_INVALID` | ContractViolation, not retried | The task's committed `values.json`, or an await's completion, could not be converted into the task's output ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Read the message, which gives the conversion error, and correct the values the task writes. |
| `ACTIVITY_TIMEOUT` | TimedOut, not retried | The activity's own start-to-close limit ended it before the Orker reported a result. That limit is built from the task's timeout, its cancellation grace period and the run's transfer budget ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). | Not retried, as for `CONTAINER_TIMEOUT`. Read the attempt's stderr, and raise `timeout_seconds` if the work legitimately takes longer. |
| `ORKER_HEARTBEAT_TIMEOUT` | InfrastructureError, retried | The Orker stopped heartbeating the activity, so it is taken to have died. That is a fact about the host, not the workload. The task is retried, which moves it to a live Orker ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#81-the-five-categories), "§8.1"). | Retried. If it keeps happening on one host, check that host. If the attempt's record says `REPORT_UNDELIVERED`, the Orker was stopped and could not tell the cluster so. |
| `ORKER_HEARTBEAT_LOST` | InfrastructureError, retried | Nothing acknowledged the attempt's heartbeat for the 30 s heartbeat timeout, because the cluster was unreachable or too slow to answer. A shorter silence changes nothing. The Orker stopped the attempt as it stops a cancelled one (`SIGTERM` to the container, `SIGKILL` after the task's grace), though nobody cancelled the task, because the cluster has given the attempt up and a retry may start elsewhere. A task that had already written its commit is not affected: it reports its result. Nor is one whose container had already exited by itself: it reports how it ended. The task itself usually reads `ORKER_HEARTBEAT_TIMEOUT`, with this on the attempt's record ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"). | Check the cluster's health and the network between it and the Orker. Give the task a `retry:` if it should survive this, since a task with none has one attempt. |
| `ATTEMPT_STORE_UNAVAILABLE` | InfrastructureError, retried | The Orker could not claim the attempt's ordinal: the attempt store refused or did not answer the claim on four tries over about 10 s. The attempt did nothing: it created no container, wrote no attempt record and streamed no log ([STORAGE.md](./STORAGE.md#invariants-the-layout-carries), "Attempt ordinals"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#71-the-sequence), "§7.1"). | Check that the object store is reachable from the Orker and accepts conditional writes under `metadata/attempts/`. The attempt runs again without spending an own attempt, five times in a row, waiting at least 45 s after the first ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"); past that, under its `retry:`. |
| `RUNTIME_STATE_UNKNOWN` | InfrastructureError, retried | The container's start failed and the container runtime could not then say whether it started: the inspect that decides it failed too, usually because the daemon stopped answering. The Orker stopped the container and removes it, but it may have run, so running the task again can repeat an external side effect; a task with one keys it on `idempotencyKey`. The attempt counts as never started, so the task runs again without spending its own attempts, five times in a row; past that, under its `retry:` ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"). | Check the Orker's container daemon (`docker info` or `podman info` as the Orker's user) and its logs. |
| `ORKER_STOPPED` | InfrastructureError, retried | The Orker running the attempt was stopped with `SIGTERM` or `SIGINT` and handed the attempt back: a running container got the cancellation sequence (`SIGTERM`, then `SIGKILL` after the task's grace) while the attempt kept heartbeating, and the Orker reported the attempt itself before it exited. It hands back only what still runs when its stop grace (`orker.stop.grace`) ends, or at a second signal; an attempt that reached the Orker after the signal started nothing. The task runs again on another Orker without spending its own attempts while its run's interruption budgets last, then under its `retry:` policy; a task with no `retry:` then fails with this reason ([DEPLOY.md](./DEPLOY.md#interruption-budgets), "Interruption budgets"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"; [DEPLOY.md](./DEPLOY.md#removing-an-orker-safely-cordon-and-drain), "Removing an Orker safely"). | Give the Orker a stop grace that covers its tasks, and a stop timeout that covers the grace, or drain it before stopping it: `orkctl orker drain ID`. |
| `REPORT_UNDELIVERED` | InfrastructureError, retried | Found only on an attempt's record (`orkctl run attempts`). The Orker handed the attempt back as it stopped but the cluster never took its report within 10 minutes, so the run sees what it sees of an Orker that died: the task ends `ORKER_HEARTBEAT_TIMEOUT`, or runs again under its `retry:` policy ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#63-heartbeats-and-cancellation), "§6.3"). | Check that the Orker reaches the cluster. |

### Run history and saved state

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_HISTORY_LIMIT` | InfrastructureError, not retried | The run would have exceeded its cluster's history limit, so it stopped explicitly instead of being terminated. Failure handlers run within the history kept back for them. The message says how much history was recorded and what was still running ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#82-reason-codes), "§8.2"). A pause or unpause request that recording would take past the limit is not applied there: a run that can carry on into a fresh history starts nothing new, carries the request on and applies it there first; one that cannot, or that already carries 64 such requests, stops with this reason and its message names the request; a run already failing, which is running or holding its failure handlers, instead drops the request, records no event for it and ends with its own reason. | Read the message and the run's details: what was running, and which pins and awaits were open. ## Pausing a run

`orkctl run pause` and `run unpause` (the API's `PauseRun` and `UnpauseRun`) check the run before they send anything, and refuse with `failed_precondition` and one of these reasons, which leads the message. The checks read the run as the read model has it, so a request can still race the run's own change; then the run's decision stands, and the request's `RUN_PAUSED` or `RUN_UNPAUSED` event, or its absence, says what it did ([API.md](./API.md#pauserunrequest), "PauseRunRequest").

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `RUN_PAUSE_UNSUPPORTED` | — | The run was started by a release without support for pausing, so it cannot be paused. | Cancel it, or let it finish. |
| `RUN_PAUSE_NOT_RUNNING` | — | The run has not started yet, or is waiting for its concurrency slot. | Cancel it if it should not continue, or pause it once it runs. |
| `RUN_ALREADY_PAUSED` | — | The run is already paused, by a person or because its parent run is paused. A pause cannot be changed. | Unpause it, or its parent run, then pause it again. |
| `RUN_PAUSE_INHERITED` | — | An unpause of a run that is paused because its parent run is paused. Only the parent's unpause lifts it. | Unpause the parent run the message names. |
| `RUN_ENDING` | — | A pause of a failing run whose failure handlers have all started, so a pause would hold nothing, or an unpause of a run whose pause has already expired and which is ending. | Read why the run ended, with `orkctl run get`. |
| `PAUSED_FILTER_UNAVAILABLE` | — | A list asked for `status=PAUSED` on a deployment whose cluster does not index paused runs. There, a paused run lists as `RUNNING`, and `orkctl run get` shows it exactly ([DEPLOY.md](./DEPLOY.md#the-paused-run-index), "The paused-run index"). | Register the `OrkflowRunPaused` search attribute and restart an engine. |

| `IMAGE_NOT_PINNED` | — (ContractViolation at the Orker) | A `uses:` value contains a template action. An image chosen at run time cannot be pinned at create. A member of an evidence bundle that is reclaimed, unrecorded or rejected carries one of six lowercase tokens as its `reason`. `orkctl run evidence verify` reports each one as a finding, not a failure, and exits 0 for it ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#verify), "verify").

|---|---|---|---|

| `definition_digest_mismatch` | — | A document exists at the run's pinned coordinates, but it does not hash to the digest the run pinned. | `commit_missing` | — | The commit record was reclaimed by cleanup. Its recorded digest is preserved ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the commit as reclaimed. Nothing to repair in the bundle. |

| `artifact_reclaimed` | — | The artifact GC deleted the object after its run was retired. Its recorded digest is preserved ([RUN_EVIDENCE.md](./RUN_EVIDENCE.md#reason-tokens), "Reason tokens"). | `verify` lists the object as reclaimed. Nothing to repair in the bundle. |

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `EVENT_SOURCES_DISABLED` | — | The deployment has event sources off: every write but a delete is refused, and a source reads `DISABLED`. | Set `event_sources.enabled` ([DEPLOY.md](./DEPLOY.md), § 1). |
| `EVENT_SOURCES_REQUIRE_AUTHENTICATION` | — | Callers are not authenticated and the operator has not accepted that for the event-source API; reads are refused too. A source written under `event_sources.allow_asserted` reads `DISABLED` with it, since no instance runs until authentication is enforced. | Enforce authentication; `event_sources.allow_asserted` lets sources be written, read and evaluated meanwhile. |
| `EVENT_SOURCES_REQUIRE_VERSIONING` | — | The deployment runs with no build id, so it is not a release, which event sources need. | Set `ORK_BUILD_ID` on `ork` and `orker` and promote the release ([DEPLOY.md](./DEPLOY.md#3-rolling-a-release-forward), "Rolling a release forward"). |
| `EVENT_SOURCE_INVALID` | — | The source breaks a bound or a rule of its own document, before anything else is read; names the field. | Fix the field. |
| `EVENT_SOURCE_LIMIT` | — | A quota or a sum is full: sources per deployment or namespace, instances, or a namespace's rate; the refusal carries the arithmetic. | Delete a source, lower a number, or raise the setting. |
| `EVENT_SOURCE_MAPPING_INVALID` | — | `input`, `map` or `artifacts` disagrees with the Orkflow's declared inputs; names the field. | Fix the mapping or the Orkflow. |
| `EVENT_SOURCE_CONFIG_INVALID` | — | `with:` disagrees with the image's declared interface, or `concurrency` is over the image's maximum; names the key. | Fix `with:`. |
| `EVENT_SOURCE_DELIVERY_MISMATCH` | — | The source's `delivery:` is not its image's declared class. | Say the image's class, or choose another image. |
| `EVENT_SOURCE_IMAGE_UNSUPPORTED` | — | The image is not a source image this release hosts (`SERVICE_CONTRACT_UNSUPPORTED`, `SERVICE_PROFILE_UNSUPPORTED`), declares its interface wrongly, or `uses:` names a first-party image, none of which ships with this release. | Name an image of the event-source profile by its registry reference. |
| `SERVICE_CONTRACT_UNSUPPORTED` | — | Carried by `EVENT_SOURCE_IMAGE_UNSUPPORTED`: the image implements no Orker Service Contract version this release hosts, or carries no `org.orkstack.service.contract` label. | Use an image built for contract version 1 ([EVENT_SOURCES.md](./EVENT_SOURCES.md#the-image), "The image"). |
| `SERVICE_PROFILE_UNSUPPORTED` | — | Carried by `EVENT_SOURCE_IMAGE_UNSUPPORTED`: the image's `org.orkstack.service.profile` label is not `event-source` at a version this release hosts. | Use an image of the event-source profile, version 1. |
| `EVENT_SOURCE_ORKFLOW_UNSUPPORTED` | — | The Orkflow declares something a run started by a message cannot be given: an await with `callback: true`, or tasks that ask for identities or credentials. | Bind another Orkflow. |
| `EVENT_SOURCE_IDENTITY_UNSUPPORTED` | — | The source declares its own identities, credentials or a secret through a grant, which need task identity. | Use `env:` or `file:` secrets the namespace allows. |
| `EVENT_SOURCE_NAMESPACE_MISMATCH` | — | An update's source names another Orkflow than the stored one, or `orkctl`'s `-n` names another namespace than its file; both are named and nothing was written. | Send it in the source's own namespace, or correct the file. |
| `EVENT_SOURCE_ID_MISMATCH` | — | A delete named a source by an id the name no longer holds; the text names the id it holds now, and nothing was deleted. | Look at the source the name holds now (`orkctl event-source get`). |
| `EVENT_SOURCE_DOCUMENT_UNREADABLE` | — | A stored source was written by a release this engine cannot read; nothing of it is answered. | Ask an engine of the release that wrote it. |
| `EVENT_SOURCE_PAUSED` | — | The state of a source an operator paused. | `orkctl event-source resume`. |
| `EVENT_SOURCE_NOT_CONVERGED` | — | The state of a stored source that runs nothing; in this release no source runs. | Nothing. |
| `MESSAGE_TOO_LARGE`, `MESSAGE_ATTRIBUTES_TOO_LARGE`, `MESSAGE_IDENTITY_INVALID`, `MESSAGE_TEXT_INVALID` | — | A message over one of its bounds: the body, the attributes (64 KiB), the identity (256 bytes, no control character), a subject or an attribute name. | Fix the producer, or raise the source's `max_bytes`. |
| `MESSAGE_NOT_JSON`, `MESSAGE_JSON_TOO_DEEP`, `MESSAGE_JSON_TOO_LARGE` | — | A `format: json` body is not one strict JSON value (with its byte offset, never its bytes), nests deeper than 64 levels, or holds more than 1 MiB of key names open at once. | Fix the producer, or read the body as `bytes`. |
| `MESSAGE_FIELD_MISSING`, `MESSAGE_FIELD_TYPE`, `MESSAGE_INPUT_TOO_LARGE` | — | A selector for a required input selected nothing, a selected value is not of the input's declared type, or a mapped value (4 KiB) or the mapped input is over its bound. | Fix the producer or the mapping. |
| `MESSAGE_NOT_MATCHED` | — | A test of `match:` did not hold; names the first. | Nothing, if the filter is meant. |
| `MESSAGE_UNPROCESSABLE` | — | The source's selectors could not be read. | Fix the selector it names. |

## Cache memo misses

A cached task whose memo cannot be used runs. Each reason below is a miss, not a failure, so the category is a dash. The task runs as though it had no memo ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"; [OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#541-memoized-completion-cache), "§5.4.1"). The memo step fails an attempt only when its own commit write fails, with `COMMIT_WRITE_FAILED`, listed above.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `MEMO_ABSENT` | — | No memo exists for this key. | None. The task runs and writes the memo ([OCI_ACTIVITY_CONTRACT.md](./OCI_ACTIVITY_CONTRACT.md#541-memoized-completion-cache), "§5.4.1"). |
| `MEMO_UNREADABLE` | — | The memo could not be read: a store error, a corrupt memo, an unknown schema, or the 30-second lookup bound passed ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `MEMO_MISMATCH` | — | The memo stored at this key describes another key, namespace, scope, task or Orkflow, or the Orker's namespace guard refused to read it ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `MEMO_EXPIRED` | — | The memoized result is older than the task's effective TTL ([DSL.md](./DSL.md#ttl-scope-and-bypass), "TTL, scope and bypass"). | None. The task runs. The task's `ttl_seconds` and the deployment's maximum TTL set the limit. |
| `SOURCE_COMMIT_GONE` | — | The run that produced the memoized result was retired, and its commit is gone ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `SOURCE_COMMIT_CHANGED` | — | The source commit's stored bytes no longer hash to the digest the memo recorded ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `SOURCE_COMMIT_UNREADABLE` | — | The source commit could not be read or decoded ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `SOURCE_COMMIT_MISMATCH` | — | The source commit is not this task's result. Its namespace, task, run, time, image digest, exit status or Orkflow differs, or the Orker's namespace guard refused it as another namespace's ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `SOURCE_OVER_LIMITS` | — | The memoized result does not fit this run's limits: values, artifact count or size, or commit size ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. The limits are deployment configuration. |
| `SOURCE_OBJECT_UNAVAILABLE` | — | The committed `values.json` is gone or corrupt, or an artifact object is gone ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs. |
| `INPUT_UNHASHED` | — | An input reference carries no digest, so no key can be computed. No memo is written ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs without a memo. |
| `MEMO_STORE_ABSENT` | — | The Orker has no memo store ([DSL.md](./DSL.md#miss-reasons), "Miss reasons"). | None. The task runs without a memo. |


## Pause warnings

A paused run tells each running child run of its pause. Each reason below is one way that did not happen, recorded on the parent run (`Run.pause_warnings`) while it stays paused and noted on the composed task. The child keeps running, so the category is a dash.

| Reason | Category | Meaning | What to do |
|---|---|---|---|
| `CHILD_NOT_PAUSABLE` | — | The child run was started without support for pausing, so it was not told. | None needed, or pause the child run itself once it supports pausing. |
| `CHILD_PAUSE_FAILED` | — | The pause could not be delivered to the child run after its retries. The message carries the error. The next pause or unpause tries again. | Read the message. Pause the child run itself if it must stop starting work. |
